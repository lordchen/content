# Simple Agent v3.6 规划：达人素材审核页

## 目标

新增一个独立页面，服务“达人素材审核”场景。

用户输入一个飞书多维表格链接后，系统读取表格中的每一行达人视频链接，识别其中的抖音或小红书视频链接，异步提取字幕，并把字幕结果回填到飞书对应字段。

这不是素材入库页的扩展，而是一个独立工作台，核心目标是：

- 面向运营审核流程
- 以飞书表格为主工作面
- 以异步任务为主执行模型
- 强调任务透明、失败可见、可重试、可局部补跑

## 为什么要独立成页

现有 `materials` 页更偏“素材入库与素材库管理”，它适合：

- 批量识别素材链接
- 入库本地素材
- 预览、补字幕、加入脚本参考

但达人素材审核场景有明显不同：

1. 数据真源在飞书，不在本地素材库
2. 主动作不是“入库”，而是“读取表格 -> 跑字幕 -> 回填表格”
3. 用户更关心任务进度、失败原因、回填状态，而不是素材详情抽屉
4. 一次处理可能是几十到几百行，更适合任务制和批次视图

因此建议独立为 `v3.6` 新页面，不与现有素材库混写。

## 页面定位

建议页面名：

- 中文：`达人素材审核`
- 路径：`/content/reviews.html`
- 对应脚本：`content-center-v3.6-reviews.js`

页面定位：

- 一个“飞书表格驱动”的审核任务工作台
- 用户从这里发起、查看、重试和追踪字幕提取任务

## 用户主流程

### 主流程

1. 用户粘贴飞书多维表格链接
2. 系统读取表格结构，识别视频链接列、字幕回填列
3. 用户先预览本次可处理的记录
4. 用户点击“开始提取字幕”
5. 系统创建异步任务
6. 后台逐行处理：
   - 读取视频链接
   - 判断平台（抖音 / 小红书）
   - 拉取字幕
   - 将字幕写回飞书对应字段
7. 页面实时显示：
   - 总数
   - 处理中
   - 成功
   - 失败
   - 最近错误
8. 用户可对失败项单独重试，或按条件批量重试

### 不建议的流程

不建议做成：

- 用户粘贴飞书链接后前端同步等待全部完成
- 一次性把所有视频都先导入本地素材库再回填
- 页面刷新后任务状态丢失

## 异步任务模型

这个页面必须走异步任务，不建议同步处理。

### 原因

1. 字幕提取本身耗时不稳定
2. 飞书写回也可能有频控或暂时失败
3. 用户可能一次处理几十条以上
4. 页面必须允许用户离开后回来继续查看结果

## 飞书读取与写回设计

现有系统里已经有：

- 飞书 base 链接解析
- 表格记录读取
- 预览逻辑

`v3.6` 可以直接复用这部分思路，但要增加：

1. 字段识别
   - 自动判断“视频链接列”
   - 自动判断“字幕列”
2. 记录级写回
   - 只更新当前记录目标字段
3. 失败隔离
   - 某一条写回失败，不影响整个任务中断

### 字段识别建议

优先规则：

- 链接列候选名：
  - `视频链接`
  - `链接`
  - `作品链接`
  - `抖音链接`
  - `小红书链接`
  - `url`
- 字幕列候选名：
  - `字幕`
  - `提取字幕`
  - `字幕结果`
  - `视频字幕`
  - `caption`

如果自动识别不到，必须要求用户手工指定。

## 用户体验要求

这个页面的重点不是“炫”，而是降低焦虑。

### 必须有的体验

1. 预览先行
   - 用户先看到“哪些行会处理”
   - 不要一粘链接就直接开跑

2. 任务可离开
   - 明确告诉用户“任务后台继续执行”
   - 用户可以切页回来再看

3. 失败可解释
   - 平台不支持
   - 视频失效
   - 字幕服务失败
   - 飞书写回失败
   - 权限不足
   - 频控

4. 可重试
   - 单条重试
   - 失败项批量重试

5. 可见进度
   - 不只是百分比
   - 还要看到成功/失败/剩余数量

### 前端文案建议

任务创建后建议直接提示：

- “任务已创建，系统会在后台逐条提取字幕并写回飞书。”
- “你可以离开这个页面，稍后回来继续看结果。”
- “失败记录不会影响已完成记录，可单独重试。”

## 性能要求

这个页面一开始就要按性能思路设计，不要等后面再补。

### 1. 首屏不要拉全量历史明细

首屏只拉：

- 最近任务摘要
- 最近一个运行中的任务摘要

不要首屏拉每个任务的全部子项。

### 2. 子项列表分页

任务子项列表必须分页或窗口化，不要一次渲染全部行。

建议：

- 默认每页 20 或 30 条
- 支持只看失败、只看成功、只看处理中

### 3. 任务轮询节流

前端轮询建议：

- 运行中任务：2 到 3 秒轮询
- 非运行中任务：停止轮询
- 页面隐藏时降频或暂停

### 4. 服务端处理限流

不要一次并发过多字幕提取。

建议：

- 单任务并发 2 到 4
- 飞书写回串行或低并发
- 失败后可短暂退避

### 5. 结果缓存

同一条记录如果已有成功字幕，不要重复提取，除非用户明确“强制重跑”。

## 推荐版本拆分

为了降低发布风险，建议不要一次把整页所有能力一起上，而是按“先打通闭环，再补体验，再补效率”推进。

### `v3.6.1` 最小闭环版

目标：

- 用户可粘贴飞书链接
- 系统可读取记录并预览
- 用户可创建异步任务
- 后台可逐条提取字幕并写回飞书
- 前台可看到任务基础进度

建议只做：

- 新页面入口与基础布局
- 飞书链接解析
- 字段自动识别与手动指定
- 任务创建接口
- 任务详情接口
- 后台逐条跑字幕
- 单条记录写回飞书
- 基础状态轮询

这版先不追求：

- 历史任务复杂筛选
- 批量重试失败项
- 复杂统计图
- 大量前端交互打磨

发布标准：

- 选一个真实飞书表，至少 10 条记录能稳定跑完
- 成功和失败都能明确展示
- 页面刷新后能继续看任务状态

### `v3.6.2` 任务管理版

目标：

- 让用户真正敢长期使用
- 让失败记录可追踪、可重试、可解释

建议补齐：

- 任务列表页摘要
- 任务详情子项分页
- 失败原因分类展示
- 单条重试
- 批量重试失败项
- 已成功字幕默认跳过，避免重复跑

发布标准：

- 用户可只重跑失败项
- 同一任务重复打开不产生重复写回
- 页面在几十到上百条记录下仍然可操作

### `v3.6.3` 性能与体验版

目标：

- 把这页从“能用”提升到“顺手”
- 控制长任务和大表格下的焦虑感

建议补齐：

- 轮询节流
- 页面隐藏时暂停或降频
- 任务摘要本地缓存
- 子项筛选与分页优化
- 处理中提示、空态、失败态统一
- 更细的任务文案与错误提示

发布标准：

- 运行中任务不会造成页面明显卡顿
- 首屏只加载摘要，打开速度稳定
- 用户在等待过程中始终知道“系统正在做什么”

## 后端边界建议

这次建议新开一组 `reviews` API，不要继续往现有 `materials` 或 `generation` 接口里硬塞。

### 第一阶段建议接口

- `POST /api/simple-agent/reviews/feishu-preview`
- `POST /api/simple-agent/reviews/jobs`
- `GET /api/simple-agent/reviews/jobs`
- `GET /api/simple-agent/reviews/jobs/:id`

### 第二阶段补充接口

- `POST /api/simple-agent/reviews/jobs/:id/retry-failed`
- `POST /api/simple-agent/reviews/jobs/:id/items/:itemId/retry`

### 接口职责

`feishu-preview`

- 只负责解析飞书链接、读取记录、识别字段、生成预览
- 不创建任务，不写数据库任务状态

`jobs`

- 根据预览确认后的输入创建任务
- 冻结本次任务使用的飞书信息、字段映射和记录快照

`jobs/:id`

- 返回任务摘要
- 返回分页后的子项
- 返回最近错误和当前进度

## 数据模型建议

建议任务创建时保留“快照”，避免飞书表中途变化导致前后结果对不上。

### `influencer_review_jobs`

除基础字段外，建议增加：

- `source_snapshot_json`
- `field_mapping_json`
- `result_summary_json`

作用：

- 保留任务创建时的输入条件
- 保留自动识别到的字段映射
- 快速给前端返回摘要，减少每次都现算

### `influencer_review_job_items`

除基础字段外，建议增加：

- `record_snapshot_json`
- `writeback_error`
- `started_at`
- `finished_at`

作用：

- 保留单条记录原始内容，方便排错
- 区分“提字幕失败”和“写回失败”
- 支撑后续耗时分析

## 用户体验底线

这个页面最重要的不是功能多，而是降低等待焦虑。

### 必须有的状态反馈

- 读取飞书时显示“正在读取表格”
- 创建任务时显示“正在创建任务”
- 任务运行时显示“后台处理中，可离开页面”
- 子项失败时显示明确原因，不只写“失败”

### 必须避免的体验

- 点击开始后页面无反馈
- 长时间只有转圈，没有数量变化
- 失败后只提示“请求错误”
- 一刷新页面就不知道任务跑到哪了

### 建议文案

- “系统正在后台逐条提取字幕并写回飞书。”
- “你现在可以离开页面，稍后回来查看进度。”
- “失败记录不会影响已完成记录，可单独重试。”

## 性能底线

这个页面默认要按“大表格、长任务”来设计。

### 前端

- 首屏只拉最近任务摘要，不拉全部明细
- 子项默认分页，每页 20 到 30 条
- 只对运行中任务轮询
- 页面切后台时暂停或降频

### 后端

- 单任务字幕提取并发控制在 2 到 4
- 飞书写回低并发，优先稳定
- 子项状态更新尽量批量提交，避免过于频繁写库
- 同链接或同记录在同任务内要避免重复处理

## 非目标

下个版本先不要做这些，避免范围失控：

- 不改 ASR 服务配置
- 不改字幕服务配置
- 不改 Feishu 配置与授权方式
- 不把所有审核记录强制入库本地素材库
- 不把达人审核页并进 `materials` 主页面
- 不做复杂图表报表

## 推荐结论

如果按稳妥发布来排，建议下一步直接按下面顺序执行：

1. 先做 `v3.6.1`，只打通“飞书预览 -> 创建任务 -> 提字幕 -> 回填飞书 -> 查看进度”。
2. 验证真实表格可稳定跑通后，再做 `v3.6.2` 的失败重试和任务管理。
3. 最后再做 `v3.6.3` 的性能与体验收口。

## 一句话结论

下一个版本最合理的方向，不是继续在素材库上叠按钮，而是新增一个独立的“达人素材审核”页，围绕“飞书链接 -> 异步字幕提取 -> 回填飞书”做成任务型工作台。
